# Create 頁面 UX 設計規格

> **v2 (2026-03-25)**：雙軌獨立分析 → 候選方案決策中心 → 統一評估

---

## 核心心智模型

**方法獨立，結果匯流。**

- 反向路徑與正向路徑是**兩條完整且獨立的分析鏈**
- 每條鏈各自跑完 TRIZ → 子系統 → SCAMPER → 路徑方案池
- 最後在**候選方案決策中心**攤平比較
- 再做統一評估（MUST / Pre-CAD）

不是「多入口進同一條主幹」。
是「**兩組人各自想辦法，最後把結果攤在同一張桌上比**」。

---

## 設計原則

| # | 原則 | 說明 |
|---|------|------|
| 1 | **雙軌分析，不是假共線** | 兩條路徑各自有自己的 TRIZ/子系統/SCAMPER 實例 |
| 2 | **方案匯流，才是決策主場** | 候選方案比較台是整個頁面的主角，不是一個小 step |
| 3 | **不是只看點子，要看假設與證據** | 每個方案必須可追溯來源、假設、驗證需求 |
| 4 | **監控不混主線** | convergence / health 是背景系統，側欄或摺疊面板 |
| 5 | **流程是上游，決策才是主角** | UI 重心在比較與決策，不在流程節點本身 |

## 資訊架構：三層結構

### 第一層：雙軌分析區（Dual Analysis Tracks）

兩條獨立分析鏈並排。每條鏈內部有自己的步驟。

#### 反向路徑（Reverse Track）

從跳脫既有框架開始，產出非典型架構，再解其引入的新矛盾。

| 步驟 | 名稱 | 說明 |
|------|------|------|
| R1 | Anti-Anchor Sprint | AI 產出 ≥3 非典型架構 + Validation Passport |
| R2 | TRIZ 解矛盾 | 針對 Anti-Anchor 引入的新矛盾，三路徑求解 |
| R3 | 子系統定義 | 識別受 Anti-Anchor 矛盾影響的子系統 |
| R4 | SCAMPER 變形 | 對子系統執行 7 種創意動作 |
| R→ | 路徑方案池 | 本路徑產出的候選集（adopted TRIZ + SCAMPER + promoted Anti-Anchor） |

#### 正向路徑（Forward Track）

從已識別矛盾直接系統化求解。

| 步驟 | 名稱 | 說明 |
|------|------|------|
| F1 | TRIZ 解矛盾 | 針對 CLD 矛盾（Phase 1 Explore 產出），三路徑求解 |
| F2 | 子系統定義 | 識別受 CLD 矛盾影響的子系統 |
| F3 | SCAMPER 變形 | 對子系統執行 7 種創意動作 |
| F→ | 路徑方案池 | 本路徑產出的候選集（adopted TRIZ + SCAMPER） |

### 第二層：候選方案決策中心（Alternative Decision Hub）

**這裡是整個頁面的主角。**

兩條路徑的方案全部攤平，橫向比較。

每個方案卡片顯示三層資訊：

**第一眼（快速判斷）**：
- 方案名稱
- 來源路徑（反向 / 正向）
- 來源步驟（TRIZ_TC / TRIZ_PC / TRIZ_SF / SCAMPER / Anti-Anchor promoted）
- 信心等級
- MUST 結果 / Pre-CAD 結果

**第二眼（好壞比較）**：
- 核心機制
- 主要優點
- 主要缺點 / trade-off

**第三眼（追溯與驗證）**：
- 關鍵假設
- 驗證需求
- 弱點
- 依附的矛盾 ID / 子系統來源
- 完整 Validation Passport（可展開）

#### 比較維度

| 維度 | 說明 |
|------|------|
| 效益 | 對目標 KPI 幫助多大 |
| 成本 | 實作與維護成本 |
| 風險 | 新矛盾 / 系統衝擊 |
| 驗證難度 | 是否容易設計實驗 |
| 落地速度 | MVP 可完成時間 |
| 可逆性 | 做錯了能不能回退 |

### 第三層：統一評估區（Unified Evaluation）

針對決策中心通過初篩的方案做正式評估。

| 評估 | 說明 |
|------|------|
| MUST 快篩 | M1-M6 必要條件（pass / fail / marginal） |
| Pre-CAD 審查 | 五維評分：MUST / 解耦 / 可驗證性 / 失效機制 / MVP CAD effort |

### 背景層：收斂監控（Convergence Monitor）

不是步驟，是橫向監控機制。側欄或摺疊面板。每條路徑各自有一組。

| 監控項 | 說明 |
|--------|------|
| Convergence Score | 收斂信心 0-100% |
| Architecture Health | healthy / warning / critical / circular |
| Fatal / Major / Minor | 各 severity 矛盾計數 |
| Risk Register | minor 矛盾清單（不阻斷） |
| Re-scan Status | 當前收斂迴圈狀態 |

## 方案追溯六要素

每個候選方案必須能追到：

| # | 要素 | 說明 |
|---|------|------|
| 1 | 來源路徑 | 反向 / 正向 |
| 2 | 來源步驟 | TRIZ_TC / TRIZ_PC / TRIZ_SF / SCAMPER / Anti-Anchor promoted |
| 3 | 解的矛盾 | contradiction IDs |
| 4 | 涉及子系統 | related subsystem IDs |
| 5 | 基於假設 | assumption list (from Validation Passport) |
| 6 | 缺少驗證 | required verifications |

## 候選方案決策中心文案

### 有方案時

> **候選方案決策中心**
> 彙整反向與正向路徑所產出的所有候選方案，供橫向比較與統一評估。

### 無方案時

> 目前尚無可比較方案。
> 請先在任一路徑完成分析鏈，或晉升 Anti-Anchor 方向為候選方案。

## 用語對照（v1 → v2）

| v1 用語 | v2 用語 | 理由 |
|---------|---------|------|
| 起始模式 | 雙軌分析區 | 不是「入口選擇」，是兩條獨立分析鏈 |
| 入口 A / 入口 B | 反向路徑 / 正向路徑 | 它們是完整路徑，不只是入口 |
| 主幹流程 | （移除） | 沒有共享主幹，各自獨立 |
| 統一匯流至主幹 | 候選方案決策中心 | 匯流的是結果（方案），不是流程 |
| Step 1-6 | R1-R4 + F1-F3 + 決策中心 + 評估 | 各路徑各自編號 |

## 產品定位

這不是單純的流程工具。它是：

**AI-assisted multi-path solution evaluation workspace**

核心價值：
- 多種分析手法都能進來
- 產生不同來源的方案
- 方案彼此可比較
- 假設與驗證可追蹤
- 最後做出更可辯護的決策
