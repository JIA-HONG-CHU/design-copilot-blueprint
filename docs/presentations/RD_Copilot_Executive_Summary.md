## 0️⃣ 解決痛點（大白話）+ 為什麼是這套系統

### 🗣 RD 每天真正在抱怨的事

| 大白話                         | 背後真相                            |
| --------------------------- | ------------------------------- |
| 「**我想不到新的**」                | 被熟悉架構綁住，探索只有 1-2 條              |
| 「**我不知道我不知道什麼**」            | 假設藏在腦袋裡，沒人逼你講出來                 |
| 「**等 CAD 才發現撞了**」           | 風險往後推，返工 3-5 次才收斂               |
| 「**老闆問為什麼選這個，我忘了**」         | 決策無追溯，經驗無法複用                    |
| 「**ChatGPT 講的我不敢信**」        | LLM 數字是「它的想像」，沒被驗證              |

### 🧠 為什麼是這套系統？—— 五個核心算法

| 算法                                   | 解決什麼           | 關鍵機制                                              |
| ------------------------------------ | -------------- | ------------------------------------------------- |
| **TRIZ 三層 Drill-Down** (L1→L2→L3)    | 經驗鎖定           | 39 參數 × 矛盾矩陣 × 40 原理 × 4 分離原則 × 76 標準解            |
| **Anti-Anchor + 第一性原理**              | 路徑依賴           | 物理原則反推 + 跨域強制類比 → ≥3 條非對標路線                      |
| **CLD 因果迴路圖**                        | 假設隱藏           | 把系統動態畫出來，找可介入斷路點                                  |
| **KT Decision Analysis**             | 決策不可追溯         | WANT/AC 結構化評分，自動生成 Decision Record                |
| **Spatial Validator**（純算術）           | LLM 幻覺         | 不呼叫 LLM，用資料庫真值覆寫估計數字                              |

> **一句話**：
> 別的 AI 幫你「生想法」，這套系統幫你 **生證據、生追溯、生反偏誤**。

## 1️⃣ 系統流程 + 核心模組

### 🔄 端到端主流程

```
[Brief]
   │
   ▼
┌─────────────────────────────────────┐
│ ① AI 結構化 (Analyst Agent)          │
│    Brief → Constraint/矛盾/假設     │
└─────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────┐
│ ② RAG 知識注入                      │
│  ├─ 企業 RAG（歷史專案 · datasheet）│
│  └─ 外部 Web Search（Tavily）       │
└─────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────┐
│ ③ CLD 因果迴路建模                   │
│    找斷路點 · 正式化矛盾            │
└─────────────────────────────────────┘
   │
   ▼
┌──────────────┐     ┌──────────────┐
│ ④ 正向 TRIZ  │ ⟵⟶ │ ⑤ Anti-Anchor│
│  L1/L2/L3    │     │  反向非對標  │
└──────┬───────┘     └──────┬───────┘
       │                    │
       ▼                    ▼
┌─────────────────────────────────────┐
│ ⑥ Decision Hub (Step 5d)            │
│    候選池 → MUST 快篩 → Pre-CAD     │
└─────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────┐
│ ⑦ 證據閉環                          │
│    Evidence Matrix + Risk Register  │
│    + KT Decision → 知識回寫         │
└─────────────────────────────────────┘
```

### 🧩 核心模組對應

| 模組                | 角色                              | 產出                                         |
| ----------------- | ------------------------------- | ------------------------------------------ |
| **AI 結構化層**       | Analyst Agent                   | 把自然語言 Brief → 結構化 Constraint / Contradiction / Assumption |
| **RAG 知識層**       | Knowledge Agent                 | 企業歷史 artifact + 外部 datasheet/文獻檢索，防 LLM 瞎編 |
| **CLD 建模器**       | 因果迴路 + TRIZ 正式化                 | 系統動態圖、斷路點、核心矛盾清單                           |
| **正向 TRIZ Solver** | L1 TC / L2 PC / L3 SF           | LayeredTrizSolution（三層同時視角）                |
| **反向 Anti-Anchor** | 第一性原理 + 跨域類比                    | ≥3 條與竞品物理不相容的路線 + Validation Passport       |
| **Decision Hub**  | 候選匯流 + MUST 快篩                  | 3-5 條晉級路線                                  |
| **證據引擎**          | Evidence Matrix + Risk Register | 假設 × 證據 × 缺口 × 風險 Owner                    |
| **純算術驗證器**        | Spatial Validator（不用 LLM）       | Package Map + 真值覆寫                         |

## 2️⃣ 核心價值 + 產出

### 💎 對 RD 的核心價值（三句話）

1. **更快**：方案探索 2 天 → **0.5 天**；返工 3-5 次 → **≤2 次**
2. **更準**：假設驗證覆蓋 <30% → **≥80%**；純算術覆寫 LLM 幻覺
3. **更值錢**：經驗從「個人腦袋」→「團隊可查的 artifact」；決策 **100% 可追溯**

### 📦 具體產出物清單

#### 三大核心報告

| 報告                                        | 內容                                 | 用途              |
| ----------------------------------------- | ---------------------------------- | --------------- |
| 📘 **MUST Rulebook**                      | M1-M6 六條硬規則 + E0-E4 證據分級           | Gate 快篩、客觀否決依據  |
| 📊 **Evidence Matrix × Risk Register**    | 關鍵假設 × 證據等級 × Top-10 風險 × Owner    | 證據缺口可視化         |
| 🔍 **Pre-CAD Review**                     | 5 維評分 + 3-5 條最優路線                  | 進 CAD 前的最後防線    |

#### 配套工件

- **Validation Passport** × N（每條路線都附假設強度 + 弱點 + 驗證項）
- **Decision Record**（KT WANT/AC 格式，簽核可追溯）
- **Interface Contract**（6 維：尺寸 / 功能 / 熱 / 振 / 控制 / 成本）
- **Knowledge Asset**（回寫企業 RAG，下一個專案的冷啟動 Seed）

### 📈 量化 KPI 對照

| 指標          | Before    | After           |
| ----------- | --------- | --------------- |
| 方案探索時間      | 2 天       | **0.5 天**       |
| 架構級返工       | 3-5 次     | **≤2 次**        |
| 假設驗證覆蓋率     | <30%      | **≥80%**        |
| 決策追溯率       | ~0%       | **100%**        |
| 單次設計評審      | 3-4 hr    | **≤2 hr**       |
| 經驗資產化       | 個人腦袋      | **團隊 artifact** |

## 3️⃣ 開發時程（PM 視角）

### 🗓 總體：6 個月、3 階段，每階段可獨立驗收

```
M1 ──── M2 ──── M3 ──── M4 ──── M5 ──── M6
├─ Phase A ──┤├─ Phase B ──┤├─ Phase C ──┤
  MVP 正向     反向 + 匯流    證據 + 結案
```

### 📋 各階段 Milestone / Deliverable / 驗收標準

| 階段          | 期程     | 主要交付                                       | 驗收標準                                 | Gate                              |
| ----------- | ------ | ------------------------------------------ | ------------------------------------ | --------------------------------- |
| **Phase A** | M1-M2  | TRIZ KB (5 份) + Forward 軌 MVP + Analyst Agent | 跑通 Step 1-3，Pilot 專案產出 Contradiction + Assumption 清單 | **Gate A**：Pilot Brief → 核心矛盾自動化識別 |
| **Phase B** | M3-M4  | Anti-Anchor Sprint + Decision Hub (5d) + Pre-CAD Review | ≥3 條非對標路線 + Validation Passport，MUST 快篩通過 | **Gate B**：候選池達到 3-5 條 + 首次 Pre-CAD Review |
| **Phase C** | M5-M6  | Evidence Matrix + Risk Register + 知識回寫 | Pilot 專案結案 + KT Decision Record 100% 追溯 | **Gate C**：Pilot 結案 + 知識沉澱進企業 RAG |

### 👥 資源需求（PM 關心）

| 項目                 | 需求                                         | 來源            |
| ------------------ | ------------------------------------------ | ------------- |
| **BD/開發團隊**        | 後端 AI (2) + 前端 (1) + BD/PM (1)              | BD 側          |
| **RD Design Partner** | 2-3 位 senior RD                            | RD 側          |
| **Pilot 專案**       | 1-2 個中風險專案                                 | RD 側挑選        |
| **歷史 Artifact**    | 過往專案決策記錄、datasheet、尺寸規格                    | RD 側提供        |
| **外部服務**           | LLM API (OpenAI/Claude) + Tavily + Supabase | BD 側採購        |

### ⚠️ 風險與緩解（PM 必問）

| 風險                 | 機率   | 緩解措施                             |
| ------------------ | ---- | -------------------------------- |
| RD 不願投入時間配合        | 高    | Phase A 結束 6 週可看成果，降低沉沒成本        |
| 歷史 Artifact 缺乏，冷啟動失敗 | 中    | 內建 eBike 種子庫 + 退化路徑保證永遠有輸出       |
| LLM 幻覺影響可信度        | 中    | 純算術驗證器 + 真值覆寫機制（Phase A 就上線）     |
| Pilot 專案選擇過難       | 中    | 建議中風險專案，避開客戶壓力最大的案子              |

### 🚦 Go / No-Go 決策點

- **M2 結束**：Gate A 通過 → 繼續 Phase B；未通過 → 調整範圍重跑
- **M4 結束**：Gate B 通過 → 繼續 Phase C；未通過 → 延長 1 個月補強
- **M6 結束**：Gate C 通過 → 進入 Future Extension（設計審查自動化、製造可行性、Simulation 介接）
